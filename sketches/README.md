## 第 3 轮（09-22）：对话优先首屏（P1 原型，3 个立场）

按《规划 v1.1》的「对话是入口 + Evidence-first」做，三版都用同一条演示问答（`ads.ads_产销存月报` 的产量怎么来的），便于对比。

| 变体 | 在线地址 | 立场 | 一句话 |
| --- | --- | --- | --- |
| `100-chat-minimal` | http://localhost:5180/100-chat-minimal/ | 极简对话（大模型式） | 只有会话列 + 居中消息流；凭证是消息里的卡片；最像 ChatGPT，学习成本最低 |
| `101-chat-workbench` | http://localhost:5180/101-chat-workbench/ | 工作台三栏（深色 Copilot） | 窄导航 + 会话列 + 对话 + 右侧「会话上下文」常驻（引用的表/口径/调用/审计） |
| `102-chat-evidence-first` | http://localhost:5180/102-chat-evidence-first/ | 凭证优先（左对话/右证据画布） | 右侧是**证据画布**（血缘图/口径/报告三个 tab），点左侧结论即可切到对应证据 |

三版共同点（P1 硬要求）：工具调用步骤条可展开看真实请求与耗时、结论带 `status`（verified/置信度/版本/来源行）、**凭证卡片**（血缘图/口径详情/HTML 报告）、无 LLM key 时以规则模式运行的提示、建议追问。

## 两轮的差别（关键）

| | 第 1 轮 v1/v2/v3 | 第 2 轮 001/002/003 |
| --- | --- | --- |
| 核心隐喻 | 「**AI 助手问答** + 知识大盘」：问一句 → 生成链路 SQL → 卡片式回答 | 「**查询工具**」：贴 SQL → 看血缘结果 → 打开报告 |
| 功能落点 | 口径卡片、分层分布、链路健康、校验徽章（**字段血缘只有一个数字**） | **真表格**的字段级血缘（目标/来源/表达式/口径四列）、按层展开的上游/下游、报告浏览屏 |
| 可交互 | 几乎无（按钮是装饰、SQL 被 `...` 截断） | 有：字段过滤、分段切换、点节点高亮链路、上下游切换、报告列表/内嵌预览 |
| 两屏 | 单屏融合（报告只是一句「查看完整报告」） | 明确两屏：**血缘查询** + **报告浏览** |
| 适合 | 讲「我们要做 AI 问数 + 数据资产运营」的**故事** | 讲「这东西现在就能用」的**工具** |

## 第 2 轮三个变体的立场对比

| 维度 | 001 工业工具风 | 002 清爽编辑风 | 003 图谱探索风 |
| --- | --- | --- | --- |
| 信息密度 | 高（三栏同屏） | 中（单列分节，往下读） | 中（图为主，细节进抽屉） |
| 主视觉 | SQL 编辑器 + 结果表 | 大标题 + 卡片流 | 血缘画布 |
| 核心动作可见性 | 高（一屏看到全部） | 中（要滚） | 高（点一下就有反馈） |
| 扫读性 | 高（工程师友好） | 最高（领导/产品友好） | 中（图好懂，细节要展开） |
| 演示冲击力 | 中 | 中 | **高**（高亮链路+光晕，讲"改一个字段影响谁"很直观） |
| 弱点 | 小字多、偏"后台味"、窄屏吃力 | 结果分散在三段，要滚动才能看全 | 表格细节弱、窄屏/小屏体验差 |
| 最适合 | 天天用的数据开发 | 汇报、评审、给业务方看 | 演示、讲影响面、做作品集封面 |

## 我的建议（不是折中，是有取舍的）

**骨架用 `002` 的排版（浅底、卡片、三段同屏），结果区引入 `003` 的血缘画布（节点高亮 + 点开详情），口径/知识部分沿用第 1 轮的"知识大盘"卡片。**

理由：
- `001` 的三栏在 1440px 以下就挤，且与海豚自带的深色 UI 撞色**反而**不好认（我们是嵌在它旁边的独立页，浅色更"像新东西"）；
- `003` 的图是这台系统**最有说服力**的表达（"改一个字段影响谁"一目了然），但整屏只有图会让"字段级血缘"这个硬能力退到抽屉里；
- 第 1 轮的「知识大盘」（75 条口径 / 298 字段 / 分层分布 / 链路健康）是很好的**第二屏**，别丢，但现在不该挤进查询屏。
