# 功能点清单与工作分解（WBS）

配套文档：《项目规划与功能设计 v1.1》§5 功能设计 ｜ 2026-09-22 ｜ 用途：**让多个开发者可以直接认领工作项**

> 规则：每个工作项（Work Item）都必须能**独立验收**——有明确的交付物、可执行的验证方式、写清的依赖。
> 规模估算：S ≈ 0.5~1 天，M ≈ 2~3 天，L ≈ 4~5 天，XL ≈ 1 周+（1 人 + AI 辅助）

---

## 0. 工作项编号规则

`W-<阶段><两位序号>`：`W-101` = Phase 1 第 01 项。标签维度：**域**（F1~F10）、**层**（前端/后端/内核/契约/运维）、**依赖**、**建议角色**。

**四个角色**（可一人多角色，也可多人同角色）：
- **FE** 前端（Vue3/TS/可视化）
- **BE** 后端（FastAPI/PG/Agent 编排）
- **KB** 内核对接（旧仓库契约、解析、口径、生成）
- **OPS** 环境与运维（compose、CI、部署、演示环境）

```
W-101 骨架 ─┬─ W-102 契约 ─┬─ W-111/112/113 后端基础 ─→ W-114 Agent(规则) ─→ W-123 对话首屏

            │                                ├─ W-124 血缘图
            │                                ├─ W-127 口径页
            │                                └─ W-128 报告页
            ├─ W-104 分层守卫  W-105 开发环境  W-106 CI
            └────────────────────────────────────────────→ W-141 一键验收 → W-142 演示固化
```

**关键路径**：`W-101 → W-102 → W-103 → W-114 → W-123 → W-141`（约 3 周串行）
**可完全并行的分支**：前端三页（W-124/127/128）与后端工具链（W-113/117/118）只要 W-102 完成即可同时开工。

## 5. 每条工作项的"完成定义"（DoD，统一标准）

1. 代码合并进 main，且有**测试**（后端单测/契约测；前端至少一个组件测试或可复现的手工验收脚本）
2. **验收方式写在工作项里**，并且真的跑过（贴输出或截图到工作项）
3. 涉及契约的：`contracts/openapi.yaml` 已同步、无破坏性变更（有则升版本并记录 ADR）
4. 涉及界面的：提供 **截图或录屏**（本项目对"用户能用"的判定标准是**视觉确认**，不是"接口通了"）
5. 文档同步：README / 规划 / ADR 任一受影响的都更新
6. 降级与错误态被覆盖（至少一条用例）
