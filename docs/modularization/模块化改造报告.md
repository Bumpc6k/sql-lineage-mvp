## 一句话

把原来「一个大包 + 一个插件目录」的单体结构，拆成 **3 个可独立部署单元 + 1 个共享内核**，
单元之间只允许通过**契约**（HTTP / CLI / 磁盘产物）耦合，并用一个**分层守卫**把这条规则变成可执行检查。

## 过程中踩到并修掉的三个真坑（都有用例兜住）

1. **路径深度**：模块下移一层后，所有用 `__file__` 推「仓库根」的地方（知识库 DB、报告目录、默认血缘图、服务根）都会指错。
   共修 8 处；`tests/test_report.py` 当场抓出 1 处。
2. **`from lineage import <模块名>` 这种拿模块对象的写法**：改写规则只覆盖 `from lineage.x import y`，漏了 4 处，测试直接报 `cannot import name 'report'`。
3. **拆分造成的循环依赖**：把「子命令注册表」放错层会让 `main → 家族 → main` 成环；最终注册表放 `graph_cmds`（唯一被家族单向依赖处），公共设施放 `common`。
