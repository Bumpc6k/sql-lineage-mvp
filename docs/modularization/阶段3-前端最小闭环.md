# 阶段 3（最小闭环）：独立前端模块 `apps/web`

日期：2026-09-21　范围：只做「能演示」的两屏，不追求工程完备

## 做了什么

平台里的**单元①**：`apps/web` —— 只通过 HTTP 调 `apps/lineage-api`，**不 import 任何后端代码**，
后端地址在页面顶部可改（存在浏览器 localStorage）。

| 屏 | 能干什么 | 用到的接口 |
| --- | --- | --- |
| **血缘查询** | 粘一段 SQL → 出「语句数 / 输入表 / 输出表 / 字段血缘 / 命中口径」五张统计卡 + 表级血缘表 + 字段级血缘表（可按表名字段名过滤）+ 命中的业务口径卡；一键跳到报告；也可按表名查**上游溯源 / 下游影响面**（按层展示 + 链路） | `POST /analyze`、`POST /upstream`、`POST /impact`、`GET /health` |
| **报告浏览** | 列出服务端已生成的 HTML 报告（时间/大小），**内嵌预览**或新窗口打开 | `GET /reports`、`GET /report/<id>` |

## 怎么起（两种方式，都验证过）

```bash
# A. 独立部署（体现「单元①独立」）—— 静态服务 :5173
bash ops/start-web.sh
#   → 浏览器开 http://localhost:5173/

# B. 蹭后端托管 —— 不起任何前端服务
bash ops/start-lineage-api.sh
#   → 浏览器开 http://localhost:18080/app/
```

演示深链接（也用于无头渲染验证）：`?demo=1` 打开就跑一次示例 SQL、`?tab=reports` 直接进报告屏、
`?table=ads.ads_产销存月报&dir=upstream` 直接查上下游。

## 技术取舍：为什么这版**没有** Vite / TS

* 本机（WSL 与 Windows 侧）**都没有 Node/npm**，装 Node 才能跑 Vite；
* 最小闭环的目标是「能演示」，所以走**零构建**：Vue 3 全局构建（`vendor/vue.global.prod.js`，3.5.43，本地内置，
  不依赖 CDN、离线可跑）+ 原生 ES 模块。**部署 = 拷目录**，208 KB。
* 升级路径不堵：`app.js` 是标准 ES 模块、模板与逻辑分离、所有接口调用集中在 `call()` 一个方法里。
  装好 Node 后可拆 `.vue` 单文件组件 + 按 `contracts/openapi.yaml` 生成 TS 类型，**目录与契约都不用动**。

## 后端为「前端独立」做的两处改动（都在 `serve/api_server.py`）

1. **CORS**：前端从 `:5173` 这类别的源调用时浏览器才放行（`Access-Control-Allow-Origin`，
   `OPTIONS` 预检返回 204；可用环境变量 `LINEAGE_CORS_ORIGIN` 收紧）。
2. **可选托管** `GET /app/`：顺手把 `apps/web` 当静态目录下发（演示省事）；不想用也完全不影响服务。
