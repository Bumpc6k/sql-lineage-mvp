# 血缘分析与数据链路生成引擎 · 设计方案

> 目标：从「解析 SQL 的插件」升级为「**能解析、能沉淀、能生成、能落地**的数据开发助手」。
> 本文是实现前的设计定稿，实现进度见文末。

```
                                   │
```

## 二、LINEAGE_DAG：工作流级血缘分析（挂尾部）

### 为什么需要它

| 方式 | 历史工作流改造量 | 跨任务血缘 |
|------|-----------------|-----------|
| 任务级（每个任务旁挂 LINEAGE）| ❌ 20 个任务挂 20 个节点 | ❌ 单任务视角 |
| **工作流级（尾部挂 LINEAGE_DAG）** | ✅ **加 1 个节点，原任务零改动** | ✅ 自动串联上下游 |

### 参数设计

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `scope` | `current` | `current` = 当前工作流；`project` = 整个项目 |
| `includeSubProcess` | `false` | 是否递归解析子工作流（SUB_PROCESS）|
| `taskTypes` | `SQL,SHELL,PYTHON` | 参与解析的任务类型 |
| `serviceUrl` | `http://172.17.0.1:18080` | 血缘服务地址 |

### 运行流程

```
① 插件（worker 内）从 TaskExecutionContext 取
      projectCode / processDefineCode / processInstanceId
      （已实测：TaskExecutionContext.getProcessDefineCode() 可用）

② 调服务端 POST /analyze-workflow
      {"project_code":..., "process_define_code":..., "scope":"current", ...}

③ 服务端（账号只配在服务端一处，插件保持"哑客户端"）
      · 登录海豚 OpenAPI → GET /projects/{pc}/process-definition/{code}
      · 遍历 taskDefinitionList，按 taskTypes 提取脚本
        （SQL → taskParams.sql；SHELL/PYTHON → taskParams.rawScript）
        ⚠️ 实测：一个 4 任务工作流可直接拿到 4 份完整 SQL（748~1086 字符）

④ 批量解析 → 合并血缘图 → 跨任务串联（按表名连接各任务的输入/输出）

⑤ 产出四类结果
      a. 全链路图谱：t_ods_产量流水 → t_dwd_产量明细 → t_dws_产量汇总 → t_ads_月报
      b. 跨任务字段血缘：哪个环节改了哪个字段（含表达式）
      c. 口径汇总：本工作流产出的所有指标及其计算口径
      d. 质量告警：断链（产出表无人消费）/ 孤岛（输入表无来源）/ 环路
```


## 三、生成引擎：从需求到可运行链路

### 能力分层

| 层级 | 能力 | 输入 | 输出 | 依赖 |
|------|------|------|------|------|
| **L1** | 单表加工 SQL 生成 | 源表 + 目标表 + 口径要求 | 完整 `INSERT OVERWRITE ... SELECT` | 知识库口径 + 字段术语 + 命名规范 |
| **L2** | 分层链路生成 | 业务需求（如"要一张产销存月报"）| 多段 SQL（ods→dwd→dws→ads）| L1 + 分层规则 + 血缘图 |
| **L3** | 调度落地 | 链路 SQL + 依赖关系 | 海豚工作流 JSON；**可选直接调 API 创建 DAG** | 海豚 OpenAPI |
| **L4** | 反向校验 | 生成的链路 | 血缘扫描报告（断链/环路/口径冲突）| 现有血缘引擎 |

### 关键设计取舍

| 设计 | 理由 |
|------|------|
| **模板引擎为主** | 生成结果确定性高、可解释、可追溯（面试能讲清"为什么这么生成"）；命名规范、分层规则、口径公式全部来自知识库 |
| **LLM 可选增强** | 无 key 时走模板（离线可用）；有 key 时用 LLM 理解模糊需求 + 润色注释 |
| **生成即校验** | 生成的 SQL 立刻过一遍血缘引擎（自校验闭环），断了链路当场报错 |
| **落地可选** | 默认只输出 SQL 供人工确认；加 `--apply` 才真正调海豚 API 建工作流（避免误操作生产）|

### 闭环

```
   解析血缘 ──► 沉淀知识库 ──► 生成 SQL/链路 ──► 编排调度（海豚）
      ▲                                                    │
      └────────────── 再解析校验 / 回流知识 ◄───────────────┘
```

## 四、差异化（面试谈资）

| 维度 | DataHub / Atlas | DataWorks 数据地图 | DB-GPT | **本项目** |
|------|----------------|------------------|--------|-----------|
| 技术血缘（表级/字段级）| ✅ | ✅ | ⚠️ 弱 | ✅ |
| 调度平台深度集成 | 弱（外挂）| 平台内 | ❌ | ✅ 原生任务节点（SPI）|
| **业务口径自动提炼** | ❌ | ❌ | ❌ | ⭐ 真空白 |
| **工作流级血缘 + 历史零改造** | ❌ | ⚠️ 需改造 | ❌ | ⭐ 挂尾节点 |
| **从需求生成链路** | ❌ | ❌ | ⚠️ 仅单条 SQL | ⭐ 链路 + 落地 |
| 部署成本 | 重（Neo4j/ES）| 平台绑定 | 中 | 轻（零依赖 Python + SQLite）|
